# Submission guide

Everything you need to get this published, in order. Total cost: ₹0. Total elapsed time: about a week.

---

## Step 0 — Before anything else

**Sanitise.** This paper must contain zero client-identifiable material. Check:

- [ ] No mention of Rolls-Royce, TCS, or any client system name
- [ ] No production numbers presented as measurements (the 52→14 min and 40% figures are *motivation*, and should appear only as "in a production system the author worked on" or be cut entirely)
- [ ] No schema, table, or column names taken from a client system
- [ ] No screenshots of internal dashboards or Spark UIs

The paper as written already satisfies this: every number comes from synthetic data generated by the harness. Keep it that way.

**Check your employment agreement.** Most Indian IT services contracts assign IP created "in the course of employment." This work is synthetic-data research done on your own hardware and time, which is normally outside that scope — but a one-line email to your manager or HR confirming you may publish independent technical research is cheap insurance, and having the reply in writing is worth more than the five minutes it costs.

## Step 1 — GitHub (day 1)

```bash
git init && git add -A
git commit -m "skewbench: benchmark and cost model for Spark skewed-join mitigation"
gh repo create spark-skew-bench --public --source=. --push
```

Before pushing, confirm:

- [ ] `make test` passes
- [ ] `make reproduce` works from a clean clone
- [ ] README renders correctly on GitHub
- [ ] `data/` and `results/eventlogs/` are gitignored (they are)
- [ ] LICENSE and CITATION.cff present

**Why this comes first:** the repo is what a senior engineer on your interview panel will actually open. It carries more weight than the PDF.

## Step 2 — Zenodo → DOI #1 (day 1, ~10 minutes)

1. Sign in at [zenodo.org](https://zenodo.org) with GitHub
2. Settings → GitHub → flip the switch on `spark-skew-bench`
3. On GitHub: Releases → Create a new release, tag `v1.0.0`
4. Zenodo mints a DOI automatically and archives the release

Add the resulting DOI badge to the README and cite it in the paper's Artifact Availability section.

---

## Step 3 — TechRxiv → DOI #2 (day 2, ~4 business days to live)

[techrxiv.org](https://www.techrxiv.org) — IEEE's preprint server.

- Free, no IEEE membership required
- DOI assigned to every accepted preprint
- Moderators screen for plagiarism, offensive content and scope **only** — IEEE states explicitly that content "is not screened for technical merit, completeness, or novelty"
- Roughly 4 business days to a decision

**Submission checklist:**

- [ ] `make paper` produces `main.pdf` cleanly
- [ ] Author name, affiliation ("Independent Researcher"), and email correct
- [ ] Zenodo DOI cited in Artifact Availability
- [ ] Category: Computer Science → Databases / Distributed Computing
- [ ] Keywords: Apache Spark, data skew, adaptive query execution, query optimization, benchmark

**Order matters.** TechRxiv rejects already-published work — *"Final versions of published articles will not be accepted or posted."* Preprint first, conference later. Never the reverse. Doing it in this order also leaves every upgrade path open.

## Step 4 — Tell people (week 1)

This is the step that actually converts, and the one most people skip.

**LinkedIn.** You already post daily and have an audience for exactly this. The post writes itself from the paper's counter-intuitive finding: *"Everyone says salt with k=16. I measured it. Here's why that's usually 4× too much, and the closed-form formula for the right number."* Link the preprint and the repo.

**Databricks Community.** The [Knowledge Sharing Hub](https://community.databricks.com/t5/community-articles/bd-p/Knowledge-Sharing-Hub) is open to non-employees, unlike Microsoft's Tech Community. Post a condensed version.

**A meetup talk.** Mumbai and Pune both have active data engineering meetups. Conference and meetup speaking is named directly by recruiters as a sourcing signal, and a talk is a far stronger hiring artifact than a PDF.

## Step 5 — The upgrade path (2027)

Once the preprint is live, submit an extended version to a real peer-reviewed venue.

| Target | Why | Cost |
|---|---|---|
| **DEEM @ SIGMOD** or **DBTest** | Workshops that specifically want practitioner-grounded empirical work. Highest status available to this paper. | Registration only |
| **Springer LNNS conference in India** (e.g. CIS at NIT Warangal) | Genuinely Scopus-indexed, accessible bar, real peer review | ~₹9,000 + travel |
| **arXiv cs.DB** | Revisit *after* a conference acceptance — that acceptance solves the endorsement problem, which is otherwise a wall for an unaffiliated first-time author | ₹0 |

**What to strengthen first for a peer-reviewed venue**, in priority order:

1. **Run it on a real cluster.** This is the single biggest upgrade. The paper predicts that `k*` is *smaller* on a cluster than on a single node, because network shuffle makes `b` larger. Confirming that prediction turns a limitation into a validated result.
2. **Use real C-MAPSS data.** `skewbench.cmapss` is already written and tested — you just need the download.
3. **Sweep θ properly.** The pilot fixes θ=1.2; `config/full.yaml` sweeps it.
4. **Add the multi-hot-key case.** `hot_keys > 1` is supported and unexercised.

## Do not

- **Do not pay IJRASET, IRJET, IJERT, JETIR, IJSREM, IRJMETS, or any "fast publication with DOI" venue.** Four of those are on Beall's List of predatory journals. None is Scopus-indexed. A recruiter cannot tell them from a real journal in a 30-second scan, but the senior engineer on your interview panel can — and the documented reaction in the literature is not "this is weak," it is *"I would start to question your integrity as a researcher."*
- **Do not** submit to a journal before TechRxiv. You lose the preprint option permanently.
- **Do not** claim cluster-scale results you did not measure. The threats section is honest; keep it that way. A reviewer who catches one overclaim discounts everything else.
- **Do not** trust any venue advertising "UGC-CARE approved" in 2026 — UGC discontinued that list in February 2025.
